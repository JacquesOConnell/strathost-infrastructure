# Machine identities

I used three EC2 roles/profiles, one each for Docker, VPN and Checkmk, plus a separate AWS Backup service role. Trust allows only the relevant AWS service to assume each role. There are no IAM users, access keys, operator administrator policies or static credentials on hosts.

Each EC2 role receives AWS's `AmazonSSMManagedInstanceCore` baseline. The root `iam.tf` attaches exact workload permissions after storage/key/secret identifiers exist: Docker site secrets, EFS access points and export writes; VPN's server-key secret; approved SSM artifacts; and Backup's source/vault keys. Checkmk's metric/inventory policy is owned by monitoring. The Backup role uses the AWS-managed service backup policy as an explicit multi-service permission exception; it is not a runtime or restore role.

The root creates empty Secrets Manager containers. Values are populated outside Terraform. The RDS administrator secret is generated by RDS and is never granted to the Docker runtime role. Existing key-admin and recovery roles remain externally owned. The root exports a proposed export-read policy for the recovery-role owner; actual EC2/EFS/RDS restore permissions and controlled role assumption require separate review.

One mocked role-separation test and schema validation pass. Policy-document data is mocked: trust evaluation, PassRole, KMS grants, access denials and real SSM sessions require account-backed tests. Account IAM delegation in the key policies follows AWS's documented pattern; workload identity policies provide the actual named-key grants.

References: [EC2 IAM roles](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/iam-roles-for-amazon-ec2.html), [SSM core policy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/AmazonSSMManagedInstanceCore.html), [Backup service role](https://docs.aws.amazon.com/aws-backup/latest/devguide/iam-service-roles.html), [KMS account delegation](https://docs.aws.amazon.com/kms/latest/developerguide/key-policy-default.html), [Terraform role](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/iam_role).
