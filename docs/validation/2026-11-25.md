Terraform verified the original AWS provider download against HashiCorp's signature. It verified Cloudflare's provider with publisher key C76001609EE3B136. Local mirror installs report unauthenticated because they reuse cached files; their dependency-lock hashes match the previously verified package selection. Generated root lockfiles are retained. AWS root/bootstrap selections include the previously obtained Windows/Linux AMD64 hashes. Cloudflare's generated lockfile is retained without claiming an additional Linux binary test.

The Terraform tests use mocked providers and `command = plan`. They make no authenticated AWS/Cloudflare deployment calls. No live Terraform plan/apply was performed.

## Reproduce local checks

With Terraform 1.17.2 on PATH and approved provider-registry access:

```powershell
pwsh -File scripts/validate.ps1 -Initialize
python -m unittest discover -s scripts/checkmk/tests -v
```

After modules are initialized, omit `-Initialize`. `-TerraformPath` selects an explicit executable. The helper runs format checking, schema validation and only the existing mocked suites. It does not run an authenticated plan/apply. On this workstation I selected `.tools/terraform-1.17.2/terraform.exe` and its isolated `TF_CLI_CONFIG_FILE`; those ignored tools are not repository dependencies for other users.

For Linux shell syntax checking, run `bash -n` against each `.sh` file. Compose needs a non-secret fixture environment and file references to parse; it does not need a daemon for the configuration check. All fixture artifacts stayed under ignored `.tools/`.
